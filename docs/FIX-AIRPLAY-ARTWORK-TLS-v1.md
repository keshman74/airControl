# airControl5.0.0 — AirPlayArtworkTLS-v1

Патч для проекта /Users/lab/AI/airControl/airControl-v5.0.0.

Исправляет источник сбоя в проверенном загрузчике Electron: команды плеера учитывают локальные TLS-сертификаты, а загрузка HTTPS-обложки AirPlay раньше использовала обычную проверку сертификата. Теперь исключение применяется только к точному пути /data/AirplayArtWorkData.jpeg на приватном IPv4 выбранного плеера. Публичные изображения и другие узлы сохраняют проверку сертификата. Правило повторно проверяется на каждом перенаправлении.

Источник изображения подтверждён пользователем на A98 192.168.0.21: getMetaInfo возвращает HTTPS URL, HTTP200,180224 байта, JPEG, Content-Type отсутствует. KNOB0.8.23 отображает эту обложку. Отсутствующий Content-Type уже поддерживался загрузчиком через image/jpeg и не является подтверждённой причиной ошибки.

Патч меняет только функцию загрузки в electron/main.cjs, четыре её вызова в src/main.jsx и добавляет electron/artwork-fetch.cjs. Установщик проверяет версию5.0.0 и исходный код функции до записи. Остальные локальные изменения сохраняются. Создаётся резервная копия; повторная установка распознаётся. Номер приложения остаётся5.0.0; идентификатор исправления AirPlayArtworkTLS-v1.

Установка:
1. Закройте запущенный airControl; в терминале с npm run dev нажмите Ctrl+C.
2. Распакуйте архив и выполните:
   python3 airControl-AirPlay-Fix-v1/scripts/apply-airplay-artwork-fix.py --project "/Users/lab/AI/airControl/airControl-v5.0.0"
3. Перейдите в эту папку и выполните npm run dev. Установка npm-пакетов не требуется.

Проверка после установки: выберите A98, запустите AirPlay, проверьте обложку, затем смените трек/альбом. Перенаправления сохраняют контекст выбранного плеера; изображение возвращается в data URL и загружается заново при обновлении приложения.
Новая аппаратная проверка airControl после патча ещё требуется. Этот патч не объявляет исправленной отдельную проблему A31, где URL вернул404.

Проверки: настоящий локальный HTTPS-сервер с самоподписанным сертификатом воспроизводит исходный отказ и подтверждает успешную загрузку исправленным модулем без Content-Type. Проверены байты data URL, ограничения по выбранному IP/пути, перенаправления, тайм-аут и обычная HTTP-загрузка.
