# Архитектура airControl Mobile

## Принцип

Текущая продуктовая версия iPhone — нативное приложение на Linkplay Music Kit. React/Capacitor сохранён как параллельный прототип общего UI и протокольной логики для будущей Android-версии, но не заменяет нативное приложение.

```text
                 ┌── iOS native app + Linkplay SDK (current)
Product UX ──────┤
                 └── Android port (planned; map in android-port/)

React/Capacitor prototype (src/, ios/, android/) remains available for
protocol logic and shared components where the platform APIs allow it.
```

## Границы

- `ios-native/`: текущий нативный iOS-клиент и источник истины по уже реализованным iPhone-сценариям.
- `android-port/`: Android-цель, экранная карта, привязка действий к логике и переносимые протоколы.
- `src/`: React-прототип, модели, HTTPAPI/UPnP и некоторые общие провайдеры каталогов.
- `ios/` и `android/`: Capacitor-оболочки прототипа, отдельные от планируемого полноценного Android-клиента.
- Протокол, не привязанный к ОС, можно переиспользовать. UIKit и iOS SDK вызовы требуют соответствующей Android-реализации или подтверждённой прямой реализации по протоколу.

## Перенос функций из нативной версии

1. Снять экран и сценарий с нативного iPhone-приложения и сопоставить их с `android-port/SCREEN-MAP.md`.
2. Для каждого действия проследить нативный контроллер и вызов SDK; сверить сетевой протокол с KB и аппаратными доказательствами.
3. Перенести UI в Android-компоненты, подключив состояние и протокольные команды через отдельный Android transport/service layer.
4. Там, где протокол общий, переиспользовать и адаптировать логику из `src/`; где есть SDK-only вызовы, реализовать аналог в Android SDK либо подтвердить эквивалентную команду.
5. Сверять на A31/A98: экран на скриншоте не доказывает, что за ним уже есть функциональная логика.

## Сейчас

Нативный проект остаётся базой текущей iOS-работы. React/Capacitor и его Android оболочка сохранены в репозитории как заготовка и источник переносимой HTTPAPI/UPnP логики. Полная Android-версия будет отдельной реализацией экранов и действий с опорой на карту в `android-port/`.
